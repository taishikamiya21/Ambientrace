# Ambientrace v1.2 — Design Spec

**作成日:** 2026-05-01
**ベースバージョン:** v1.1.0+2 (App Store リリース済み)
**対象ブランチ:** `feature/v1.2`
**ステータス:** Approved by user / Reviewed by Codex

---

## 0. 背景と目的

v1.1 リリース後のフィードバックと展示用途を踏まえ、以下を達成する。

1. データの可搬性（エクスポート/インポート）と、展示用途のカード一括出力を可能にする
2. カード枚数の増加に対応した整理機能（フォルダ）を導入する
3. カラーパレットがグレー寄りになる課題を彩度ベースの抽出ロジックで解消する
4. AI 解析機能の意図と挙動をオンボーディングと設定で明示する
5. 展示文脈に合わせた表現を選べるよう、プロンプトプリセットを導入する
6. API キー保管をセキュアストレージに移行する

v1.2 は **Phase A（基盤）と Phase B（一括処理ワークフロー）** の二段階で実装し、Phase A 完了時点で TestFlight 内部配布、Phase B 完了後にパブリック申請する。

## 3. データモデル

### 3-1. TraceLog (既存・拡張)

```dart
class TraceLog {
  // 既存フィールド (変更なし)
  final String id;
  final DateTime capturedAt;
  final DateTime createdAt;
  final double? latitude;
  final double? longitude;
  final String? placeName;
  final double? temperature;
  final String? weatherCondition;
  final double? noiseLevel;
  final int? stepCount;
  final List<String> imageLabels;
  final List<int> colorPalette;
  final String? aiDescription;

  // 新規フィールド
  final String? originalFileName;   // 取り込み元ファイル名（一括取り込み時のみ非 null）
  final String? aiProviderUsed;     // 'gemini' | 'openai' | 'claude' | 'mlkit' | null
}
```

`fromJson` は両フィールドを optional として扱い、v1.1 のデータを破壊しない。

### 3-2. Folder (新規)

```dart
class Folder {
  final String id;            // UUID v4
  final String name;
  final DateTime createdAt;
  final List<String> traceIds; // 正規データ。重複なし、追加順を保持
}
```

- 1 トレースは複数フォルダに所属可能
- フォルダ削除時、所属トレースは削除しない
- `FolderService` 起動時に `Map<traceId, Set<folderId>>` の逆引きインデックスをメモリ上に構築

### 3-3. BulkJob / BulkJobItem (新規・Phase B)

```dart
enum BulkJobStatus { pending, analyzing, generated, failed, skipped, cancelled }

class BulkJobItem {
  final String localPhotoPath;
  final String originalFileName;
  BulkJobStatus status;
  String? errorMessage;
  int retryCount;
  DateTime? startedAt;
  DateTime? finishedAt;
  String? createdTraceId;     // 成功時のみ
}

class BulkJob {
  final String id;
  final String? targetFolderId;
  final List<BulkJobItem> items;
  final DateTime createdAt;
}
```

未完のジョブは永続化し、再起動で `pending` に戻して再開可能にする。

## 4. 永続化と Migration

### 4-1. SharedPreferences キー

| キー | 型 | 説明 |
|------|----|------|
| `trace_logs` | JSON 配列 | 既存。トレース本体 |
| `folders` | JSON 配列 | 新規。Folder の永続データ |
| `bulk_jobs` | JSON 配列 | 新規・Phase B。未完のジョブ |
| `schema_version` | int | 新規。永続化スキーマのバージョン |
| `selected_llm_provider` | int | 既存 |
| `selected_prompt_preset` | int | 新規。`PromptPreset` enum index |

### 4-2. flutter_secure_storage キー

| キー | 説明 |
|------|------|
| `api_key_gemini` | v1.1 から移行 |
| `api_key_openai` | v1.1 から移行 |
| `api_key_claude` | v1.1 から移行 |

### 4-3. Migration（v1 → v2）

起動時に `StorageService.migrate()` が `schema_version` を読む。

- 未設定または `< 2` のとき:
  1. `gemini_api_key` / `openai_api_key` / `claude_api_key` を SharedPreferences から取得
  2. `flutter_secure_storage` に複製
  3. SharedPreferences 側のキーを削除
  4. 既存 TraceLog の `originalFileName` / `aiProviderUsed` は null のままで問題なし（fromJson が optional 扱い）
  5. `schema_version` を `2` に更新
- 各ステップで例外が発生した場合は **元データを保持し** `schema_version` を上げない。`debugPrint` で日本語のエラーログを残し、設定画面でユーザーに再試行を促すバナーを出す

## 5. カラー抽出 (C-5)

### 5-1. アルゴリズム

`ColorService.extractColors(ImageProvider)` を多段化する。

**Stage 1 — Vibrant Targets:**

```dart
PaletteGenerator.fromImageProvider(
  imageProvider,
  maximumColorCount: 16,
  targets: [
    PaletteTarget.vibrant,
    PaletteTarget.lightVibrant,
    PaletteTarget.darkVibrant,
    PaletteTarget.muted, // 全画像に共通する補助
  ],
);
```

vibrant 系から最大 3 色を取得。

**Stage 2 判定:**

Stage 1 の結果のうち、HSV 彩度が 0.25 を超える色が 1 色未満、かつ取得色数が 3 未満の場合のみ Stage 2 を実行。

**Stage 2 — HSV フィルタ + 量子化:**

1. `image` パッケージで画像を 256px 長辺へ縮小
2. 各ピクセルを HSV へ変換し、`saturation > 0.30` かつ `value > 0.20` のピクセルだけを残す
3. 残ったピクセルに対して Median Cut（K=3）で量子化
4. 出現頻度上位 3 色を取得

**併合と仕上げ:**

Stage 1 + Stage 2 を併合し、重複を取り除いて最大 5 色に揃える。5 色未満なら従来の dominant で補完。

### 5-2. しきい値の取り扱い

しきい値（`S>0.30`, `V>0.20`, Stage2 判定 `0.25`）は **仮説扱い** とし、実装中に `assets/test_images/palette/` の 10 枚（展示候補・低彩度・高彩度の混合）でゴールデンテストを作って調整する。

### 5-3. 印刷時の注意

カラー出力は sRGB 前提。ICC プロファイルは保証しない。展示印刷ではプリンター側のカラーマネジメントで運用する。アプリ内の Export ダイアログにこの旨を一行注記する。

## 6. フォルダ機能 (C-6)

### 6-1. 操作 UX

**ホーム画面:**

- ヘッダー直下に Folder セレクタ（`All` / 各フォルダ）を追加
- 既存のタグフィルタ・天気フィルタと **AND 結合**
- セレクタ以外は既存レイアウトを維持

**詳細画面:**

- 「フォルダに追加 / 外す」を Bottom Sheet で複数選択
- 既存の削除アクションと並列に配置

**設定画面:**

- 「Folder Management」エントリを追加 → `folder_management_screen.dart` へ遷移
- 一覧、新規作成、リネーム、削除（確認付き）、所属トレース一覧

### 6-2. FolderService API

```dart
abstract class FolderService {
  Future<List<Folder>> listFolders();
  Future<Folder> createFolder(String name);
  Future<void> renameFolder(String id, String newName);
  Future<void> deleteFolder(String id);   // トレースは削除しない
  Future<void> addTraceToFolder(String traceId, String folderId);
  Future<void> removeTraceFromFolder(String traceId, String folderId);
  Set<String> foldersOf(String traceId);  // 逆引き(メモリ)
  Future<List<TraceLog>> tracesIn(String folderId, List<TraceLog> all);
}
```

### 6-3. 整合性

- 単一の正規データは `Folder.traceIds[]` のみ
- アプリ起動時に `Map<traceId, Set<folderId>>` をメモリ構築
- トレース削除時は所属する全フォルダから traceId を取り除く
- 重複 ID は `Set` で除去

## 7. データ I/O (C-1, C-2, C-4)

### 7-1. JSON エクスポート

```json
{
  "schemaVersion": 2,
  "exportedAt": "2026-05-01T12:00:00+09:00",
  "appVersion": "1.2.0",
  "traces": [ /* TraceLog.toJson() */ ],
  "folders": [ /* Folder.toJson() */ ]
}
```

### 7-2. CSV エクスポート

1 行 1 トレース。ヘッダ行付き、UTF-8 + BOM。

**列順:**

`id, schemaVersion, capturedAt, createdAt, originalFileName, latitude, longitude, placeName, weatherCondition, temperature, noiseLevel, stepCount, atmosphericTime, imageLabels, colorPaletteHex, aiDescription, aiProviderUsed, folderNames`

**整形ルール:**

- `imageLabels` と `folderNames` はセミコロン (`;`) 区切り
- `colorPaletteHex` は `#RRGGBB;#RRGGBB;...`
- 日時は ISO8601（タイムゾーン付き）
- セル内のカンマは引用符でエスケープ

### 7-3. JSON インポート

**競合解決モード（UI で選択）:**

| モード | 動作 |
|--------|------|
| `skip` | 同 ID は無視 |
| `overwrite` | 全フィールドを上書き |
| `duplicate` | 新 ID を払い出して複製挿入 |
| `merge` | 既存に無いフィールドのみ追記。フォルダ所属は和集合 |

**バリデーション:**

- `schemaVersion` を確認。不一致時は migration を試みる
- 必須フィールド（`id`, `capturedAt`）が欠けるアイテムは失敗としてリストアップ
- インポート前に **dryRun** で件数と問題箇所を表示してから実行

### 7-4. UI

設定画面に「Data Management」セクションを追加。

- 📤 **Export** → 形式選択（JSON / CSV / 両方）→ 位置情報含めるか確認 → `share_plus` で保存・共有
- 📥 **Import** → ファイルピッカー → dryRun 結果表示 → 競合モード選択 → 実行 → 結果サマリ

## 8. カード出力 (C-7・Phase B)

### 8-1. オプション

- ☑️ **Reconstructed Memory テキストを含める**（既定 ON）
- ☑️ **元画像ファイル名を小さく入れる**（既定 OFF。展示用途では ON 推奨）
- 解像度プリセット: `Standard (1080px)` / `A4 (2480x3508 @300dpi)` / `A3 (3508x4961 @300dpi)`

### 8-2. ファイル名

`card_{safeOriginalName}_{traceId}.png`

- `safeOriginalName`: 拡張子除去、OS 禁止文字 (`/\:*?"<>|`) を `_` に置換、長さは 60 文字まで
- `originalFileName` が null のときは `card_{traceId}.png`

### 8-3. 一括出力

- 対象選択: フォルダ または タグ から選択
- 出力 ZIP の構造:
  ```
  cards/
    card_xxx.png
  index.csv         ← 元画像名と traceId、出力ファイル名の対応表
  manifest.json     ← schemaVersion, exportedAt, params
  ```
- 進捗ダイアログ + キャンセル
- メモリ対策: 順次 RepaintBoundary → toImage → file へ書き出し（一括でメモリに積まない）

## 9. 一括カード化 (C-3・Phase B)

### 9-1. ジョブキュー

`BulkCaptureService` がキューを永続化（`bulk_jobs` キー）。

- 同時実行: **2 並列**
- リトライ: 失敗 1 回につき指数バックオフ（1s, 2s, 4s）。最大 3 回
- 状態遷移: `pending → analyzing → generated | failed | skipped | cancelled`
- アプリを閉じても再起動で再開（`analyzing` は `pending` に戻す）
- iOS / Android のバックグラウンド制限により「アプリ起動中のみ進行」と明記

### 9-2. UI

**`bulk_import_screen.dart`:**

- 写真複数選択（`image_picker` の multi 対応 or `file_selector`）
- プレビューグリッド
- 投入先フォルダの選択（既存 or 新規作成）
- 開始ボタン

**`bulk_progress_screen.dart`:**

- 進捗バー、各アイテムの状態、推定残時間、概算 LLM コスト目安
- キャンセル、失敗時のリトライ
- Wi-Fi 限定実行オプション（`connectivity_plus` を導入）

### 9-3. EXIF メタデータ抽出

- 撮影日時 (`DateTimeOriginal`) があれば `capturedAt` に充てる
- GPS があれば `latitude / longitude` に充てる
- 撮影日時から天気は Open-Meteo の **過去データ API** で逆引き

EXIF が無い場合は現在時刻・位置情報なしで生成する。

## 10. AI 解析 UX (C-8, C-10)

### 10-1. オンボーディング

末尾に **1 ページ追加**: 「AI Enrichment」

- 「設定で AI を有効にすると、写真から空気感タグと Reconstructed Memory が自動生成されます」
- 「未設定の場合は端末内 ML Kit による基本タグのみが付きます」
- 「設定はあとで変更できます」+ 設定画面への CTA

### 10-2. 設定画面 AI セクション

```
[AI Provider]
○ Gemini   [Active]   ⓘ
○ ChatGPT  [Configured]
○ Claude   [Not Set]

[Prompt Style]
[ Minimal | Poetic ✓ | Documentary | Exhibition ]   ⓘ

[How priority works] ← Bottom Sheet
[What is AI Provider?] ← Bottom Sheet
```

**バッジルール:**

- `Active`: 現在選択中、API キー設定済み
- `Configured`: API キー設定済み、未選択
- `Not Set`: API キー未設定

**Bottom Sheet 文（JP / EN 両対応）:**

- 「How priority works」: 「現在の挙動: 選択中のプロバイダーのみが使われます。複数キーを設定していても自動で切り替わりません。LLM が失敗した場合のみ ML Kit にフォールバックします。」
- 「What is AI Provider?」: 「タグ生成と Reconstructed Memory の品質を上げる外部 AI です。月間無料枠あり (Gemini)、有料 (OpenAI / Claude)。API キーは端末内に暗号化保存されます。」

### 10-3. プロンプトプリセット (C-10)

`PromptPreset` enum を `lib/services/prompt_preset_service.dart` に定義し、`LlmService.buildAnalysisPrompt` / `buildStoryPrompt` に注入する。

| Preset | 解析タグ | Memory 文体 |
|--------|----------|-------------|
| Minimal | 短い名詞句 3-5 個 | 1 文・10 語以内 |
| Poetic（既定・現行と同等） | 5-7 感覚的フレーズ | 1-2 文の詩的散文 |
| Documentary | 客観的な視覚要素 5-7 | 1-2 文の事実描写 |
| Exhibition | 展示キャプション風 5-7 | 2 文・余韻のある叙述 |

選択は `selected_prompt_preset` に永続化。設定変更は **新規生成のみに適用**（既存トレースは影響しない）。

### 10-4. fallback 挙動の明示

`image_labeling_service.dart` の `getLabels` の挙動（LLM → ML Kit fallback）は変更しない。spec とアプリ内ヘルプに明記する。`TraceLog.aiProviderUsed` には実際に使われたプロバイダ名を保存する（`'gemini' | 'openai' | 'claude' | 'mlkit'`）。

## 11. セキュリティ (C-9)

- `flutter_secure_storage` を導入し、API キーを iOS Keychain / Android Keystore で管理
- 新規設定時は secure storage に直接保存
- v1.1 → v1.2 の migration で SharedPreferences の API キーを secure storage へ移行 → SharedPreferences から削除
- Export ファイルには **API キーを含めない**
- 位置情報を含むトレースを Export するときは「位置情報を含めるか」のトグルを表示する

## 15. リスクと注意点

- **メモリ使用量**: ZIP 作成時は逐次書き出しを徹底。一括処理時のサムネイルキャッシュも明示破棄
- **API レート制限**: Gemini / OpenAI / Claude いずれも 1 分あたりの上限がある。同時実行 2 とリトライ間隔で吸収
- **バックグラウンド制限**: iOS / Android ともにバックグラウンド実行は限定的。「アプリ起動中のみ進行」を UI 上で明示
- **後方互換**: v1.1 の JSON 形式を `originalFileName` / `aiProviderUsed` 不在で受け入れる
- **インポート信頼性**: 壊れた JSON を dryRun で検証し、ユーザーに件数と問題箇所を提示してから書き込む
- **EXIF プライバシー**: 一括取り込み時、EXIF GPS の利用について明示的にユーザーへ確認する

## 17. 用語

- **Trace / TraceLog**: 1 回のキャプチャで生成されるアンビエントデータ
- **Reconstructed Memory**: トレースデータから生成される短い詩的文章
- **Atmospheric Time**: 撮影時刻を 8 区分に丸めたラベル（Late Night / Dawn / Morning / Midday / Afternoon / Dusk / Evening / Late Night）
- **Phase A**: 基盤機能群（Export / Import / Folder / Color / UX / Security / Preset）
- **Phase B**: 一括処理ワークフロー（Bulk Capture / Card ZIP）
